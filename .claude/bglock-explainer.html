spag4d · depth_correction="bglock"

Locking the background, letting the foreground move

How spag4d/video.py and spag4d/flow_depth_propagation.py turn a per-frame monocular depth estimate — noisy in time and noisy across pixels — into a depth sequence where the static ERP background is frozen to a single reference and only the masked dynamic object is re-estimated, with bidirectional optical flow carrying its depth forward frame to frame.

01The problem it replaces

The camera is fixed and the panorama is equirectangular (ERP). A monocular depth model (DA360) run independently on every frame gives a plausible depth map each time, but the same background pixel gets a slightly different depth from one frame to the next — pure estimator noise, not scene change. The legacy depth_correction="affine" path (align_depth_frame) tries to fight this after the fact: fit a per-frame scale/shift s·D + t to the current static pixels, aligning them back toward a reference depth. That's a correction bolted onto noise — it reduces drift but can't remove frame-to-frame flicker that isn't a simple affine offset, and an occasional bad frame (monocular depth derails on a small statistic of static pixels) still produces a visible depth pop.

Key insight

A fixed camera means every pixel outside the moving object is background whose true depth is constant in time — and it's already known, artifact-free, from one clean reference estimate (DA360 on the temporal-median background image, depth_ref_np). There is nothing to re-estimate there. Don't correct the per-frame noise on the background — refuse to introduce it in the first place, and spend the whole per-frame depth budget on the part of the frame that actually changes: the dynamic-mask region.

02Two depth sources per frame

Every frame after the first produces its final depth as a composite of two disjoint-by-design signals:

  • Locked background — depth_ref_np, computed exactly once from DA360 run on the temporal-median background frame. Zero temporal variance by construction.
  • Propagated object depth — this frame's dynamic-mask region (SAM3 ∪ activity mask, fused_mask), built from the fresh monocular estimate but temporally stabilized by warping last frame's finished depth forward with dense optical flow, only falling back to the raw monocular value where the warp can't be trusted.

composite_bg_locked blends the two with a feathered mask; getting the object signal right is what propagate_depth_via_flow and its bidirectional flow input are for.

Fig. 1 — one frame through run_video's loop (video.py:819–844). The object branch (top) produces a temporally-propagated dynamic-region depth; the locked branch (bottom) is a constant lookup. composite_bg_locked is the only place they meet. Its output becomes next frame's depth_prev_final — the dashed loop — so the object's depth trajectory keeps compounding forward instead of resetting to raw monocular every frame.

03Bidirectional flow: computing it

flows_fwd/flows_bwd are computed once, up front, for every consecutive frame pair — before the main per-frame loop even starts (video.py:486–500). This is a second, dedicated WAFT pass: the first pass (model.run()) only keeps flow magnitude masks for SAM prompting and discards the dense vector field. Bg-lock needs the real per-pixel displacement, in both directions.

Why both directions, not just t→t+1:

  • Forward flow (t-1→t) is what actually warps last frame's finished depth into this frame's pixel grid.
  • Backward flow (t→t-1) exists purely to grade the forward flow: composing the two should cancel out to zero displacement wherever the flow is genuinely reliable. Wherever it doesn't cancel, that's flagged untrustworthy — occlusion, disocclusion, or a WAFT failure — and the pipeline stops trusting the warp there.

Fig. 2 — compute_bidirectional_flow + confidence derivation (flow_depth_propagation.py:91–158). Both frames are wrap-padded before inference so an object crossing the ERP seam doesn't read as a teleport to WAFT (which has no notion that the panorama wraps); flow is cropped back to native width after. The forward/backward pair then yields a per-pixel trust signal that propagate_depth_via_flow consumes directly.

Resolution handling

WAFT runs on frames downscaled to ≤1024px on the long side (correlation cost). When that happens, upscale_flow resizes the flow field back to native resolution and rescales the displacement magnitudes by the same x/y factors — resizing the field alone would leave the vectors pointing the right direction but at the wrong pixel scale.

04Forward-backward consistency → per-pixel confidence

fb_consistency_error warps flow_bwd backward along flow_fwd (reusing the same seam-aware, pole-clamped warp_backward sampler used for depth) and adds it to flow_fwd. If the two flows were a perfect inverse pair the sum cancels to zero everywhere; the residual magnitude is the FB error in pixels. fb_trust = fb_err < fb_err_threshold (default 1.5 px) marks the field reliable. Two ERP-specific failure modes are masked out unconditionally on top of that:

  • Occlusion/disocclusion — flagged directly by a high FB error, no special casing needed.
  • Pole singularity — near the top/bottom rows, a full ERP row can represent a near-point on the sphere; a small angular motion there produces a huge, unstable pixel-space flow that WAFT was never trained on. pole_trust_mask(pole_margin_frac=0.08) zeroes trust in that band unconditionally — flow is never allowed to override the monocular fallback there, regardless of what the FB check says.

frame_confidence = fb_trust · pole_trust is this frame's raw trust map — before it meets the decay logic below.

05Warping depth forward, and the decay that re-anchors it

propagate_depth_via_flow (flow_depth_propagation.py:228–290) is called once per frame (after the first) with last frame's finished composite, this frame's aligned monocular depth as fallback, the reference depth, the forward/backward flow pair for this transition, and a PropagationState carried across the whole sequence.

  1. depth_propagated = warp_backward(depth_prev_final, flow_fwd) — samples depth_prev_final at p − flow(p) per pixel, wrapping x modulo W (seam) and clamping y (no wraparound over the poles).
  2. running_confidence = min(frame_confidence, state.confidence · decay) — trust can never exceed what this frame's FB/pole check allows, and it multiplies down by decay=0.85 for every consecutive step since it was last reset to 1.0.
  3. depth_final = running_confidence·depth_propagated + (1−running_confidence)·depth_curr_affine — a blend, never a hard switch.
  4. Disocclusion special-case: pixels with low confidence that are not inside this frame's dynamic mask are, on a fixed camera, revealed static background by definition — so they're set directly to depth_ref instead of the noisier fresh monocular value.
  5. State update: confidence resets to 1.0 wherever this frame's flow was itself trustworthy (frame_confidence > 0), otherwise keeps the decayed value — so decay only accumulates over an unbroken run of untrusted/propagated frames.
Why the decay exists — the blind spot flow can't see

Optical flow only measures apparent 2D displacement. An object moving straight along the camera ray — toward or away from a fixed camera — has near-zero flow but a real depth change. A pure "replace with the warped value" strategy would freeze that object at a stale depth forever. Because confidence decays every consecutive propagation step whether or not the FB check objects, the depth is continuously pulled back toward the fresh (noisier, but unbiased) monocular estimate — radial drift gets re-anchored every few frames instead of compounding indefinitely.

06Locking the background: composite_bg_locked

This is the step that actually gives the method its name. depth_object (the output of step 05, or the raw aligned depth on frame 0) is composited against depth_ref_np using a soft mask built by feather_dynamic_mask:

  • Dilate the binary fused_mask by bg_lock_dilate_px (default 12px) — covers DA360's depth-bleed halo around moving edges and any one-frame lag in the mask.
  • Gaussian-blur by bg_lock_feather_px (default 9px) — removes the hard seam between object and locked background.
  • Both operations wrap-pad horizontally first, so an object straddling the ERP seam feathers correctly instead of getting a hard edge at column 0/W−1.

The blend itself is depth_final = α·depth_object + (1−α)·depth_ref, with one guard: where depth_ref is NaN (a pixel that was masked in every single frame during background construction — see always_masked_mask in run_video — so there is no clean reference to fall back to), α is forced to 1 and the reference term to 0, so the NaN can't poison the blend and the object depth cleanly fills what would otherwise be a hole.

The result is both this frame's Gaussian-splat input and next frame's depth_prev_final — closing the loop in Fig. 1.

07Parameters

depth_correction
must be "bglock" to enable this path; requires alignement_mask ∈ {"sam", "sam_and_activity"} — bg-lock needs a real dynamic mask, not just an activity heuristic (video.py:383–387).
bg_lock_dilate_px
default 12 — mask dilation before feathering; covers depth-bleed halo + mask lag.
bg_lock_feather_px
default 9 — Gaussian blur radius for the object/background alpha transition.
flow_seam_pad
default 64px — circular horizontal padding before WAFT inference, both directions.
fb_err_threshold
default 1.5px — forward-backward consistency error above which flow is not trusted.
pole_margin_frac
default 0.08 — top/bottom row fraction where propagation is never trusted regardless of FB error.
decay
0.85 — PropagationState confidence multiplier per consecutive propagated step; hardcoded in run_video (flow_state = PropagationState(decay=0.85)), not currently exposed as a CLI/function parameter.

08Measured effect

From the internal benchmark (.claude/depth_stability_benchmark.md) on a 150-frame 2048×1024 clip with a person moving in an otherwise-static room (dynamic mask ≈3% of frame):

methodbg temporal std (m)bg p2p flicker (m)fg temporal std (m)
affine (legacy)0.09740.03220.3536
flow-prop only0.08470.00590.2797
bglock0.00010.00000.2367

Background temporal std drops ~1000× (0.097 m → 0.0001 m) because it's no longer estimated at all past frame 0 — it's a lookup. Foreground std is also lower than plain affine alignment (0.237 m vs 0.354 m), a side effect of the object depth itself being flow-propagated rather than independently re-estimated every frame.

09Known limits

  • Mask-quality dependent. Locking is only as good as fused_mask: a moving-object pixel the mask misses gets frozen to background depth for that frame.
  • Radial motion is mitigated, not solved. The confidence decay re-anchors to monocular depth every few frames rather than freezing forever, but there's still a lag — an object moving purely along the camera ray will show some staleness within each decay window.
  • Second WAFT pass cost. Bidirectional flow for every consecutive pair is a dedicated pass distinct from the magnitude-mask pass already used for SAM prompting — roughly 2× the flow compute of that first pass (forward + backward vs. forward-only), negligible next to DA360 + SAM3 cost per the original investigation notes.
